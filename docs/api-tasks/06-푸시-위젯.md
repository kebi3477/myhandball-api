# 06. 푸시와 위젯 — 득점 알림, 위젯용 경량 엔드포인트

득점·경기 시작 푸시를 보내고, 홈스크린 위젯이 쓸 가벼운 엔드포인트를 만듭니다.

**선행: 04번(폴링 워커)이 끝나 있어야 합니다.** 그리고 04번의 전제
("경기 중 점수가 실시간 갱신된다")가 **검증됐어야** 합니다.
검증이 안 됐다면 아래 "폴링이 안 되는 경우"만 진행하세요.

## 배경

시안에 홈스크린 위젯 명세가 따로 있습니다 (`MyHandball Widget.dc.html`).
small(170x170) / medium(364x170), 라이트·다크, 4상태:

| 상태 | 조건 | 표시 | 갱신 |
|---|---|---|---|
| 대기 | 오늘 MY팀 경기, 시작 전 | 시작 시각, 양팀 로고 | 시작 시각에 1회 |
| **LIVE** | 시작 ~ 종료 | **실시간 스코어, 득점 시 강조** | **득점 이벤트 푸시** |
| 종료 | 종료 ~ 당일 23:59 | 최종 스코어, 패배팀 흐리게 | 종료 시 1회 |
| 다음 경기 | 익일 00:00~ | 다음 경기 D-day | 자정마다 |

시안 주석에 "iOS 라이브 액티비티 / Android 위젯"이라고 명시돼 있습니다.

### 위젯은 앱이 아니라 네이티브다 — 알아둘 것

**홈스크린 위젯과 라이브 액티비티는 Flutter가 그리지 못합니다.**
iOS는 SwiftUI(WidgetKit/ActivityKit), Android는 Kotlin(Glance)으로 따로 짭니다.
이 API가 할 일은 **그 네이티브 코드가 쓸 데이터를 가볍게 주는 것**뿐입니다.

위젯은 배터리·네트워크 제약이 심해서 `/api/schedule` 같은 큰 응답을 파싱할 수
없습니다. 그래서 전용 엔드포인트가 필요합니다.

## 만들 엔드포인트

### 위젯용 — `GET /api/widget/my-team`

```
GET /api/widget/my-team?teamNum=132&gender=M
```

```ts
export interface WidgetResponse {
  /** 위젯이 그대로 상태 분기에 쓴다 */
  state: "pre" | "live" | "finished" | "next";

  matchSeq: number | null;
  startsAt: string | null;        // ISO 8601
  dateLabel: string | null;       // "11.14 (토)"
  timeLabel: string | null;       // "14:00"
  ddayLabel: string | null;       // "D-6"  (state가 next일 때)

  home: { name: string; shortName: string; logoUrl: string | null };
  away: { name: string; shortName: string; logoUrl: string | null };

  scoreHome: number | null;
  scoreAway: number | null;
  minuteLabel: string | null;     // "전반 18'" (live일 때)
  venue: string | null;

  /** 위젯이 다음 갱신을 언제 예약할지. ISO 8601 */
  nextRefreshAt: string;
}
```

**응답이 작아야 합니다.** 위 필드 외에 넣지 마세요. 5KB를 넘기지 않게.

`shortName`은 위젯 좁은 폭용 축약형입니다 (`인천도시공사` → `인천`).
`/record/player.php`가 쓰는 축약형과 맞추면 좋습니다.

`nextRefreshAt` 규칙:

- `pre` → 경기 시작 시각
- `live` → 60초 후
- `finished` → 다음 날 00:00
- `next` → 다음 날 00:00 (D-day 재계산)

### 푸시 토큰 등록 — `POST /api/push/register`

```ts
// 요청
{
  token: string;              // FCM 토큰
  platform: "ios" | "android";
  teamNum: number | null;     // 마이팀. null이면 팀 알림 없음
  gender: "M" | "W";
}
```

헤더 `X-Device-Id` 필수 (05번과 같은 값). 같은 기기의 재등록은 덮어쓰기.

```ts
// src/push/push-token.entity.ts
@Entity("push_tokens")
@Unique(["deviceId"])
export class PushToken {
  @PrimaryGeneratedColumn() id: number;
  @Column() deviceId: string;
  @Column() token: string;
  @Column({ type: "varchar" }) platform: "ios" | "android";
  @Column({ type: "int", nullable: true }) teamNum: number | null;
  @Column({ type: "varchar" }) gender: "M" | "W";
  @Column({ default: true }) enabled: boolean;
  @UpdateDateColumn() updatedAt: Date;
}
```

```
DELETE /api/push/register    구독 해제 (X-Device-Id 기준)
```

## 푸시 발송

`firebase-admin`을 씁니다. FCM 하나로 iOS·Android 둘 다 보냅니다
(iOS는 APNs 키를 Firebase 콘솔에 등록해야 함).

`.env`에 추가:

```
FCM_PROJECT_ID=
FCM_CLIENT_EMAIL=
FCM_PRIVATE_KEY=
```

**`.env.example`에도 키 이름을 추가**하고, 값이 없으면 푸시 모듈이 조용히
비활성화되게 하세요 (로컬 개발에서 막히지 않도록).

### 언제 보내는가

04번 폴링 워커가 이벤트를 만들 때 훅을 겁니다.

| 트리거 | 대상 | 내용 |
|---|---|---|
| 경기 시작 10분 전 | 그 경기 두 팀을 마이팀으로 둔 기기 | "곧 경기가 시작돼요" |
| **득점** | 같음 | "SK호크스 12 : 10 인천도시공사" |
| 경기 종료 | 같음 | "경기 종료 — SK호크스 28 : 26 승" |

### 득점 푸시는 반드시 묶어서 보내세요

핸드볼은 **한 경기에 두 팀 합쳐 50골이 넘습니다.** 득점마다 푸시를 보내면
사용자가 앱을 지웁니다.

```
득점 발생 → 120초 창을 열고 모아서 1회 발송
창이 열려 있는 동안의 추가 득점은 최신 스코어로 덮어쓰기
```

FCM `collapse_key`(Android) / `apns-collapse-id`(iOS)를 경기별로 지정해
**알림 센터에 한 줄만 쌓이게** 하세요.

라이브 액티비티(iOS 16.2+)를 쓴다면 이건 `content-state` 업데이트라 소리 없이
갱신됩니다. 그 경우 별도 토큰 채널이 필요하니, **먼저 일반 푸시부터** 만들고
라이브 액티비티는 앱 쪽 네이티브 작업과 함께 잡으세요.

## 캐시

- `/api/widget/my-team` — **캐시하지 않습니다.** `MatchState`를 직접 읽습니다.
  단 DB 조회가 가벼워야 하니 `matchSeq` 인덱스를 확인하세요

## 검증

```bash
# 위젯 — 종료된 경기가 있는 팀
curl -s 'http://localhost:3000/api/widget/my-team?teamNum=132&gender=M' | jq
```

기대:

- `state`가 4개 중 하나
- 응답 크기 5KB 미만: `curl -s ... | wc -c`
- `nextRefreshAt`이 상태에 맞는 시각

```bash
# 푸시 등록
curl -s -X POST 'http://localhost:3000/api/push/register' \
  -H 'X-Device-Id: test-device-0001' -H 'Content-Type: application/json' \
  -d '{"token":"dummy","platform":"ios","teamNum":132,"gender":"M"}' | jq

# 중복 등록이 덮어쓰기인지
curl -s 'http://localhost:3000/api/push/register' -X POST \
  -H 'X-Device-Id: test-device-0001' -H 'Content-Type: application/json' \
  -d '{"token":"dummy2","platform":"ios","teamNum":149,"gender":"M"}' | jq
```

푸시 실제 발송은 FCM 자격증명이 있어야 확인됩니다. 없으면 **발송 대신 로그만
남기는 드라이런 모드**를 만들어 두고, 로그에 대상 기기 수와 메시지가 찍히는지
확인하세요.

## 폴링이 안 되는 경우 (04번 검증 실패)

경기 중 점수가 갱신되지 않는다면 **LIVE 관련을 전부 빼고** 이것만 만드세요:

- `/api/widget/my-team` — `pre` / `finished` / `next` 3상태만.
  `live`는 반환하지 않음
- 푸시는 **경기 시작 알림과 종료 알림만**. `startsAt`과 종료 추정 시각
  기반이라 폴링이 필요 없습니다
- 득점 푸시, 라이브 액티비티는 보류

이 경우 앱·위젯 쪽 디자인도 줄여야 하므로 **사용자에게 보고**해 주세요.
