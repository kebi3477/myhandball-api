# 05. 사용자 콘텐츠 — 승부 예측·MVP 투표·응원글

사용자가 만드는 데이터를 서버에 저장하고 집계합니다.
**앞의 작업들과 성격이 다릅니다** — 스크래핑이 아니라 진짜 백엔드 기능입니다.

## 배경

Flutter 앱에 이미 화면이 다 있고, **지금은 전부 기기에만 저장**됩니다
(시안의 `localStorage` 키를 그대로 이어받은 구조):

| 기능 | 화면 | 현재 저장 위치 | 문제 |
|---|---|---|---|
| 승부 예측 | 경기 상세 > 예측 탭 | 기기 | 다른 사람 예측 분포를 볼 수 없음 |
| MVP 투표 | 경기 상세 > MVP 탭 | 기기 | 득표율이 가짜 |
| 응원글 | 팀 상세 > 응원 탭 | 기기 | 다른 사람 글이 안 보임 |

시안은 셋 다 **집계된 결과**를 보여주도록 그려져 있습니다 (예측 분포 막대,
MVP 득표율 바, 응원글 목록과 좋아요). 서버 없이는 성립하지 않습니다.

## 인증이 없다 — 설계의 핵심 제약

이 앱은 **회원가입이 없습니다.** 온보딩에서 성별·연령·마이팀만 고르고 끝입니다.
그래서 "한 사람이 한 번만 투표"를 보장할 수 없습니다.

### 채택할 방식: 익명 기기 ID

앱이 기기별로 UUID를 한 번 만들어 저장하고, 요청 헤더로 보냅니다.

```
X-Device-Id: 8f3a2b1c-...
```

- 서버는 이 값을 그대로 저장해 **중복 투표만 막습니다**
- 앱 재설치하면 새 ID가 됩니다. 그 정도 허용합니다
- **개인정보가 아닙니다.** 기기를 식별하지 않도록 앱이 생성한 난수 UUID입니다
- 헤더가 없으면 400

`X-Device-Id`가 없는 요청은 조회만 허용하고 쓰기는 거부하세요.

### 어뷰징 대비 (최소한)

완벽한 방어는 불가능하지만 기본은 갖춥니다:

- 같은 `X-Device-Id`로 같은 경기에 예측·투표 1회
- 응원글은 기기당 팀별 하루 5개 제한
- IP 기준 분당 30요청 rate limit (`@nestjs/throttler`)
- 응원글 본문 200자 제한 (시안과 동일)

## 데이터 모델

`src/welcome/welcome.entity.ts`가 기존 TypeORM 예시입니다.
`synchronize: true`로 개발 중이니 엔티티만 추가하면 테이블이 생깁니다.

```ts
// src/engagement/prediction.entity.ts
@Entity("predictions")
@Unique(["matchSeq", "deviceId"])
export class Prediction {
  @PrimaryGeneratedColumn() id: number;
  @Index() @Column() matchSeq: number;
  @Column() deviceId: string;
  @Column({ type: "varchar" }) pick: "home" | "draw" | "away";
  @CreateDateColumn() createdAt: Date;
}

// src/engagement/mvp-vote.entity.ts
@Entity("mvp_votes")
@Unique(["matchSeq", "deviceId"])
export class MvpVote {
  @PrimaryGeneratedColumn() id: number;
  @Index() @Column() matchSeq: number;
  @Column() deviceId: string;
  /** 02번의 player_seq. 선수를 특정할 수 없으면 이름을 쓴다 */
  @Column({ type: "int", nullable: true }) playerSeq: number | null;
  @Column() playerName: string;
  @CreateDateColumn() createdAt: Date;
}

// src/engagement/cheer.entity.ts
@Entity("cheers")
export class Cheer {
  @PrimaryGeneratedColumn() id: number;
  @Index() @Column() teamNum: number;
  @Column({ type: "varchar" }) gender: "M" | "W";
  @Column() deviceId: string;
  @Column({ length: 200 }) text: string;
  @Column({ default: 0 }) likes: number;
  @Column({ default: false }) hidden: boolean;   // 신고·차단용
  @CreateDateColumn() createdAt: Date;
}

// src/engagement/cheer-like.entity.ts
@Entity("cheer_likes")
@Unique(["cheerId", "deviceId"])
export class CheerLike {
  @PrimaryGeneratedColumn() id: number;
  @Index() @Column() cheerId: number;
  @Column() deviceId: string;
  @CreateDateColumn() createdAt: Date;
}
```

## 만들 엔드포인트

`src/engagement/` 모듈 하나에 모읍니다.

### 승부 예측

```
GET  /api/game/:matchSeq/prediction        내 예측 + 분포
POST /api/game/:matchSeq/prediction        { pick: "home" | "draw" | "away" }
```

```ts
export interface PredictionResponse {
  matchSeq: number;
  myPick: "home" | "draw" | "away" | null;   // X-Device-Id 없으면 null
  total: number;
  home: number;      // 표 수
  draw: number;
  away: number;
  /** 경기 시작 전까지만 true. startsAt 기준 */
  open: boolean;
}
```

- **경기 시작 후 POST는 409.** `startsAt`(01번)으로 판정
- 같은 기기의 재투표는 **덮어쓰기** (시안: "경기 시작 전까지 바꿀 수 있어요")

### MVP 투표

```
GET  /api/game/:matchSeq/mvp
POST /api/game/:matchSeq/mvp               { playerSeq, playerName }
```

```ts
export interface MvpCandidateItem {
  playerSeq: number | null;
  playerName: string;
  teamName: string;
  statLine: string;       // "8골 3AS" — 01번 선수 기록에서 생성
  votes: number;
}

export interface MvpResponse {
  matchSeq: number;
  open: boolean;          // 경기 종료 후에만 true
  myVote: number | null;  // playerSeq
  total: number;
  candidates: MvpCandidateItem[];   // 득표 내림차순
}
```

- **경기 종료 전 POST는 409.** 04번의 `MatchState.status`로 판정
- **재투표 불가** (시안: "한 번만 투표할 수 있어요"). 이미 있으면 409
- 후보 목록은 **01번의 `detail_player_record.php` 기록에서 상위 5명**을 뽑아
  주세요 (득점 + 어시스트 기준). 04번 폴링이 경기 종료를 감지하면 한 번 계산해
  캐시하면 됩니다

### 응원글

```
GET    /api/team/:teamNum/cheer?gender=M&page=1
POST   /api/team/:teamNum/cheer            { text }
DELETE /api/team/:teamNum/cheer/:cheerId   본인(같은 deviceId)만
POST   /api/team/:teamNum/cheer/:cheerId/like     토글
```

```ts
export interface CheerItem {
  id: number;
  text: string;
  likes: number;
  liked: boolean;        // 내가 눌렀는지
  isMine: boolean;
  createdAt: string;
}

export interface CheerListResponse {
  teamNum: number;
  total: number;
  page: number;
  items: CheerItem[];    // 최신순
}
```

- 페이지당 20개
- `hidden: true`인 글은 목록에서 제외
- **작성자 표시는 "익명"입니다.** 닉네임 입력이 없으므로 앱은 `isMine`으로
  "내 글" 뱃지만 답니다. 서버가 이름을 만들어내지 마세요

## 운영상 짚을 것

**이건 사용자 생성 콘텐츠라 신고·차단 수단이 없으면 위험합니다.**
최소한 `hidden` 컬럼으로 수동 차단이 가능하게 해 뒀습니다. 실제 서비스 전에는
신고 엔드포인트나 관리자 수단이 필요하다는 점을 사용자에게 알려 주세요.

욕설 필터는 이번 범위가 아닙니다. 필요하면 별도 작업으로 잡습니다.

## 검증

```bash
DEV='X-Device-Id: test-device-0001'

# 예측
curl -s -X POST 'http://localhost:3000/api/game/5490/prediction' \
  -H "$DEV" -H 'Content-Type: application/json' -d '{"pick":"home"}' | jq
# → 경기가 이미 끝났으므로 409 기대

curl -s 'http://localhost:3000/api/game/5490/prediction' -H "$DEV" | jq

# 응원글
curl -s -X POST 'http://localhost:3000/api/team/132/cheer?gender=M' \
  -H "$DEV" -H 'Content-Type: application/json' -d '{"text":"오늘도 화이팅!"}' | jq

curl -s 'http://localhost:3000/api/team/132/cheer?gender=M' -H "$DEV" \
  | jq '{total, first: .items[0]}'

# 헤더 없이 쓰기 → 400
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  'http://localhost:3000/api/team/132/cheer?gender=M' \
  -H 'Content-Type: application/json' -d '{"text":"x"}'
```

기대:

- 종료된 경기 예측 POST → `409`
- 응원글 작성 후 목록에 `isMine: true`로 나옴
- `X-Device-Id` 없는 POST → `400`
- 같은 기기가 같은 글에 like 두 번 → 토글되어 0으로 돌아옴

## 앱 쪽에 알려야 할 것

이 작업이 끝나면 앱은 기기 저장에서 서버로 갈아타야 합니다.
**기존에 기기에 쌓인 예측·투표·응원글을 서버로 옮길 방법은 없습니다**
(deviceId가 그때는 없었음). 앱 쪽에서 마이그레이션 없이 새로 시작하는 게
맞다는 점을 알려 주세요.
