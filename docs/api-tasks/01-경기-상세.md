# 01. 경기 상세 — `GET /api/game/:matchSeq`

경기 하나의 전·후반 점수, 팀 기록 비교, 선수별 기록을 주는 엔드포인트를 만듭니다.

## 배경

Flutter 앱의 **경기 상세 화면**이 이 데이터를 씁니다. 홈 카드·일정 카드·MY 탭
세 곳에서 열리는 화면이고, 탭이 4개입니다:

| 탭 | 쓰는 데이터 | 이 작업 범위 |
|---|---|---|
| 중계 | 시간순 이벤트 | ❌ 04번에서 |
| **기록** | **전·후반, 슛 성공률, AS/TF/ST/BS/YC/2Min** | ✅ |
| 예측 | 사용자 투표 | ❌ 05번에서 |
| **MVP** | **선수별 경기 기록** (후보 산출용) | ✅ |

지금은 전부 목업이라 실제 기록이 안 나옵니다.

## 데이터 출처

`.env`의 `BASE`(`https://www.koreahandball.com`) 기준입니다.

### match_seq를 어디서 얻는가

`/game/schedule_list.php`의 각 경기 행에 상세 링크가 들어 있습니다:

```html
<tr id='1763132400'>
  <td class="center" rowspan="2">2025.11.15 (토)</td>
  <td>15:20</td>
  <td>남</td>
  <td class="game_score">
    <div class="team home"><span class="name">두산</span><img src="..."></div>
    <a href="detail.php?match_seq=5490" class="score">
      <span class="lose">20</span> : <span class="win">23</span>
    </a>
    <div class="team away">...</div>
  </td>
```

**`<tr>`의 `id`가 경기 시작 시각의 Unix epoch(초)입니다.** 04번 폴링 워커가 이걸
씁니다. 이번 작업에서도 기존 `ScheduleService`가 `GameItem`에 다음 두 필드를
추가하도록 해 주세요 (기존 필드는 그대로 두고 **추가만**):

```ts
export interface GameItem {
  // ... 기존 필드 유지 ...
  matchSeq: number | null;   // detail.php?match_seq= 값
  startsAt: string | null;   // <tr id> epoch → ISO 8601
}
```

### `/game/detail.php?match_seq=5490`

실측한 마크업입니다.

**전·후반 점수** — `table_wrap record schedule_detial` 안의 표. 홈이 왼쪽 `<td>`,
가운데가 라벨, 원정이 오른쪽 `<td>`:

```html
<tr><td>10</td><td class="center">전반전1</td><td>10</td></tr>
<tr><td>10</td><td class="center">후반전2</td><td>13</td></tr>
```

**슛 종류별 성공률** — `div.circle_chart` 안의 도넛 차트 6종.
라벨은 영문입니다: `Total shots`, `6pm shots`, `wing shots`, `9pm shots`,
`7pm shots`, `fast shots`. 각 항목에 홈/원정 퍼센트가 붙습니다
(예: `48.7%` : `51.3%`).

**약어 기록 표** — 전·후반 표와 같은 3열 구조:

```html
<tr><td>6</td><td class="center">AS</td><td>10</td></tr>
<tr><td>6</td><td class="center">TF</td><td>7</td></tr>
```

약어 뜻 (페이지의 "용어설명" 팝업 `div.popup_record`에 정의가 있으니 확인해서
반영하세요):

| 약어 | 뜻 |
|---|---|
| AS | 어시스트 |
| TF | 실책 (턴오버) |
| ST | 스틸 |
| BS | 블록슛 |
| YC | 경고 (옐로카드) |
| 2Min | 2분 퇴장 |
| RC | 퇴장 (레드카드) |
| DR | 드리블 반칙 |

### `/game/detail_player_record.php?match_seq=5490`

선수별 경기 기록. 표 헤더 2단입니다:

```
1단: 선수 | 슛 | 공격 | 수비 | 리바운드 | 처벌 | 출전시간
2단: 배번 | 이름 | 득점/슛 | % | 필드 득점/슛 | % | 6m | 윙 | 9m | 7m | 속공 | 돌파 | EG | E7 | ...
```

값은 `"4/6"` 같은 **성공/시도** 형식이고 퍼센트는 `"66.67%"` 문자열입니다.
**숫자로 쪼개서 주세요** — 앱에서 문자열 파싱하지 않도록.

## 만들 엔드포인트

```
GET /api/game/:matchSeq
```

`src/game/` 모듈을 새로 만들고 기존 3개 모듈의 구조(controller / service /
types.ts)를 따라 주세요.

## 응답 스펙

```ts
// src/game/types.ts

export interface TeamStatLine {
  key: string;          // "totalShots" | "shots6m" | "shotsWing" | ... | "assists" | "turnovers" | ...
  label: string;        // "전체 슛" | "어시스트" — 한국어 표시명
  home: number;
  away: number;
  unit: "count" | "percent";
}

export interface PlayerGameRecord {
  number: number | null;      // 배번
  name: string;
  goals: number;              // 득점
  shots: number;              // 슛 시도
  fieldGoals: number;
  fieldShots: number;
  shots6m: string;            // "2/4" 원본 유지 (세부는 아래 숫자 필드로)
  goals6m: number;
  attempts6m: number;
  goalsWing: number;
  attemptsWing: number;
  goals9m: number;
  attempts9m: number;
  goals7m: number;
  attempts7m: number;
  goalsFast: number;          // 속공
  attemptsFast: number;
  playTime: string | null;    // "27:14"
}

export interface GameDetailResponse {
  url: string;
  matchSeq: number;
  dateLabel: string;          // "2025.11.15 (토) 15:20"
  startsAt: string | null;    // ISO 8601
  venue: string | null;       // "티켓링크 라이브 아레나(핸드볼경기장)"

  home: { name: string; logoUrl: string | null };
  away: { name: string; logoUrl: string | null };

  scoreHome: number | null;
  scoreAway: number | null;

  // 전·후반. 원본이 "전반전1" / "후반전2" 라벨을 쓴다
  firstHalfHome: number | null;
  firstHalfAway: number | null;
  secondHalfHome: number | null;
  secondHalfAway: number | null;

  stats: TeamStatLine[];

  players: {
    home: PlayerGameRecord[];
    away: PlayerGameRecord[];
  };
}
```

### 주의

- **`scoreText` 같은 문자열 점수를 새로 만들지 마세요.** 숫자로 줍니다
- 홈/원정 구분은 마크업의 `div.team.home` / `div.team.away`를 따릅니다
- 승패 표시는 `<span class="win">` / `<span class="lose">` / `draw`로 붙어 있으니
  점수 추출 시 클래스에 의존하지 말고 텍스트를 쓰세요 (무승부 클래스명 확인 필요)
- 선수 기록 표가 홈/원정 두 덩어리로 나뉘어 있는지, 한 표에 섞여 있는지
  **직접 받아서 확인하고** 그에 맞게 파싱하세요

## 캐시

- 종료된 경기: TTL 24시간 (기록이 바뀌지 않음)
- **진행 중일 수 있는 경기는 캐시하지 마세요.** `startsAt` 기준으로 지금이
  경기 시작 ~ 시작+3시간 사이면 캐시를 건너뜁니다. 04번 폴링이 여기 의존합니다

## 검증

```bash
curl -s 'http://localhost:3000/api/game/5490' | jq '{
  matchSeq, dateLabel, venue,
  score: [.scoreHome, .scoreAway],
  half: [.firstHalfHome, .firstHalfAway, .secondHalfHome, .secondHalfAway],
  statCount: (.stats | length),
  homePlayers: (.players.home | length)
}'
```

기대값 (2025.11.15 두산 vs SK호크스):

```json
{
  "matchSeq": 5490,
  "venue": "티켓링크 라이브 아레나(핸드볼경기장)",
  "score": [20, 23],
  "half": [10, 10, 10, 13],
  "statCount": 14,
  "homePlayers": 12
}
```

`statCount`는 슛 6종 + 약어 8종 = 14가 기준이지만, 용어설명 팝업에서 확인한
실제 항목 수에 맞춰도 됩니다. 선수 수는 실제 엔트리에 따라 다릅니다.

일정 쪽 추가 필드도 확인:

```bash
curl -s 'http://localhost:3000/api/schedule?gender=M&season=2025&type=1&month=11' \
  | jq '.days[0].games[0] | {matchSeq, startsAt, scoreText}'
```

`scoreText`가 **그대로 남아 있어야** 합니다 (기존 웹 호환).

## 파싱이 깨질 때

원본 사이트가 바뀌어 파싱이 실패하면 500이 아니라:

- 전·후반을 못 읽으면 해당 필드만 `null`
- 통계표를 못 읽으면 `stats: []`
- 선수 기록을 못 읽으면 `players: { home: [], away: [] }`

그리고 각각 `warn` 로그를 남깁니다. 앱은 빈 상태를 처리할 수 있습니다.
