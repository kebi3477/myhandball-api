# API 작업 지시서

마이핸드볼 Flutter 앱(`../myhandball-app`)이 필요로 하는 API 작업을 순서대로 쪼갠
문서입니다. **각 파일은 그 자체로 하나의 프롬프트**입니다 — 이 저장소만 열어둔
Claude Code 세션에 파일 내용을 그대로 붙여넣으면 됩니다.

앱 저장소를 보지 않아도 수행할 수 있도록 각 문서가 자기완결적으로 쓰여 있습니다.

## 순서

번호대로 진행합니다. 앞 단계가 뒤 단계의 파서·타입을 만듭니다.

| # | 문서 | 내용 | 선행 |
|---|---|---|---|
| 00 | [00-부트스트랩.md](00-부트스트랩.md) | `CLAUDE.md` 작성, 공통 규칙 확정 | — |
| 01 | [01-경기-상세.md](01-경기-상세.md) | `GET /api/game/:matchSeq` — 전·후반, 팀 기록, 선수별 기록 | 00 |
| 02 | [02-선수-도메인.md](02-선수-도메인.md) | `GET /api/player` 3종 — 명단·상세·기록 랭킹 | 00 |
| 03 | [03-팀-상세.md](03-팀-상세.md) | `GET /api/team/:teamNum` — 구단 소개, 코칭스태프, 팀 기록 | 00 |

01·02·03은 서로 독립이라 순서를 바꾸거나 나눠 진행해도 됩니다.
**04는 01이 끝나야** 시작할 수 있습니다 (폴링할 파서가 먼저 있어야 함).

## 앱이 지금 어떤 상태인지

Flutter 앱은 **시안의 모든 화면이 이미 구현돼 있고**, 데이터만 목업입니다.
앱 쪽 데이터 계층은 이렇게 생겼습니다:

```
HandballApiService (추상)
  └─ MockHandballApiService   ← 지금 이것만 있음
  └─ HttpHandballApiService   ← 이 API가 준비되면 추가할 구현
```

즉 **API 응답 모양이 정해지면 앱은 구현체 하나만 추가하면 됩니다.**
각 문서의 "응답 스펙"이 앱의 도메인 모델과 1:1로 맞춰져 있으니 그대로 지켜주세요.

## 공통 규칙 (모든 문서에 적용)

### 하위 호환

기존 React 웹(`_legercy/myhandball/apps/web`)이 `/api/schedule`, `/api/ranking`,
`/api/team`을 쓰고 있습니다. **필드 추가는 되지만 제거·타입 변경은 안 됩니다.**
웹을 내린 뒤라면 그때 지시서에 명시하겠습니다.

### 데이터 출처

전부 `https://www.koreahandball.com` 스크래핑입니다 (`.env`의 `BASE`).
`robots.txt`는 `User-agent: * / Allow: /` 로 전면 허용돼 있습니다.

기존 서비스가 쓰는 공통 쿼리 파라미터:

| 파라미터 | 값 | 의미 |
|---|---|---|
| `league_gender` | `M` / `W` | 남자부 / 여자부 |
| `league_season` | `2025` | **시작 연도**. 2025 = 25-26 시즌 |
| `league_type` | `1` / `2` | 정규리그 / 포스트시즌 |
| `league_season_month` | `11` | 월 (일정에서만) |

### 캐시

`CacheService`(Redis)를 씁니다. 기존 팀 목록은 TTL 24시간입니다.
문서별로 권장 TTL을 적어뒀습니다. **경기 중 데이터는 캐시하면 안 됩니다** (04 참조).

### 검증

각 문서 끝의 `curl` 예시가 기대대로 나오면 완료입니다.
스크래핑은 원본 사이트 개편에 취약하므로, **파싱 실패 시 500이 아니라 빈 배열/
null을 돌려주고 로그를 남기는** 방향으로 만들어 주세요. 앱은 빈 상태 화면을 갖고
있어서 죽지 않습니다.

## 소스 조사 결과 (2026-09-23 실측)

프롬프트를 쓰기 전에 연맹 사이트를 직접 확인한 결과입니다. 각 문서의 셀렉터는
아래 페이지를 실제로 받아서 확인한 값입니다.

| 페이지 | 쓸 데이터 | 문서 |
|---|---|---|
| `/game/schedule_list.php` | 일정, **`<tr id>`가 경기 시작 epoch**, `detail.php?match_seq=` 링크 | 01·04 |
| `/game/detail.php?match_seq=N` | 전·후반 점수, 슛 종류별 성공률, AS/TF/ST/BS/YC/2Min/RC/DR | 01 |
| `/game/detail_player_record.php?match_seq=N` | 선수별 경기 기록 (배번·이름·슛·6m·윙·9m·7m·속공·돌파) | 01 |
| `/record/player.php` | 선수 시즌 기록 전체 | 02 |
| `/introduce/player_detail.php?player_seq=N` | 선수 프로필 + 통산·시즌별 기록 | 02 |
| `/game/playerranking.php` | 카테고리별 선수 랭킹 | 02 |
| `/introduce/team_men.php?team_num=N` | 구단 소개·코칭스태프·선수·팀기록 | 03 |
| `/record/compare.php` | 선수 비교 (참고용) | 02 |

### 아직 검증 못 한 것 — 중요

**경기 중에 점수가 실시간으로 갱신되는지 확인하지 못했습니다.** 조사 시점이
비시즌(개막 11월)이라 종료된 경기만 볼 수 있었습니다.

04번 폴링 워커와 06번 푸시는 **이 가정 위에 서 있습니다.** 개막 후 실제 경기
하나를 지켜보고, 경기 도중 `detail.php`의 점수가 올라가는지 먼저 확인해 주세요.
만약 종료 후에만 반영된다면 04·06은 설계를 다시 해야 합니다 (04 문서에 판별
방법을 적어뒀습니다).
