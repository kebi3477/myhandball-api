# 03. 팀 상세 — `GET /api/team/:teamNum`

구단 소개·코칭스태프·소속 선수·팀 기록을 주는 엔드포인트를 만듭니다.

## 배경

Flutter 앱의 **팀 상세 화면**(분석 > 팀 카드, MY > 팀 상세보기, 검색 결과에서
진입)이 4개 탭을 갖고 있습니다:

| 탭 | 쓰는 데이터 | 이 작업 범위 |
|---|---|---|
| **소개** | **구단 소개문, 창단·연고지·홈구장·감독, 연혁** | ✅ |
| **전적** | **순위·승점·득실 + 시즌 추이** | ✅ (일부) |
| **선수** | 소속 선수 | ✅ (02번과 연계) |
| 응원 | 사용자 응원글 | ❌ 05번에서 |

지금은 소개문·연혁·주소가 전부 "자리표시 문구"로 하드코딩돼 있습니다.

## 데이터 출처

### `/introduce/team_men.php?team_num=132` (여자부는 `team_women.php`)

기존 `TeamService`가 **파라미터 없이** 이 페이지를 받아 팀 목록만 뽑고 있습니다.
`team_num`을 붙이면 그 팀의 상세 페이지가 나옵니다.

실측 내용 (SK호크스, `team_num=132`):

```
SK호크스
[탭] 구단소개 | 코칭 스태프 소개 | 선수 소개 | 팀기록
인스타그램 링크

소개
안녕하세요, SK호크스 핸드볼팀 입니다.
SK호크스 핸드볼팀은 핸드볼을 통해 국민들에게 감동과 행복을 주는 스포츠 구단이
되기 위해 2016년 2월에 창단하였습니다.
SK호크스는 SK하이닉스의 사업장이 있고, 핸드볼 명문인 청주공고, 일신여고 등
핸드볼 저변 활용이 가능한 청주시를 연고로 선택하였습니다.
...
```

**탭 4개가 각각 별도 URL인지, 같은 페이지의 앵커인지 확인하세요.** 별도 URL이면
탭마다 받아야 합니다. `href`를 확인하면 바로 알 수 있습니다.

- **구단소개** — 소개 본문. 창단 연도·연고지가 본문에 녹아 있습니다
- **코칭 스태프 소개** — 감독·코치 이름과 직책
- **선수 소개** — `player_detail.php?player_seq=` 링크 목록.
  **02번의 선수 목록과 이걸로 팀-선수를 연결합니다**
- **팀기록** — 팀 단위 시즌 기록

### 기존 순위 데이터 재사용

순위·승점·승무패·득실은 **이미 `/api/ranking`이 주고 있습니다**
(`RankItem.played/wins/draws/losses/goalsFor/goalsAgainst/last5`).
새로 긁지 말고 `RankingService`를 호출해 합쳐 주세요.

### 시즌 추이 — 확인 필요

앱의 전적 탭에 **라운드별 순위 추이 그래프**가 있습니다. 연맹이 라운드별 순위를
제공하는지 확인하세요. `/game/teamranking_part.php`가 힌트일 수 있습니다.

**없으면 만들지 마세요.** 대신 `/api/schedule`의 해당 팀 경기 결과로 승패 배열만
주고, 그래프는 앱이 누적 승점으로 그립니다. 응답 스펙의 `results`가 그 용도입니다.

## 만들 엔드포인트

```
GET /api/team/:teamNum?gender=M&season=2025&type=1
```

기존 `src/team/` 모듈을 확장합니다. **`GET /api/team`(목록)은 그대로 둡니다** —
기존 웹이 씁니다.

## 응답 스펙

```ts
// src/team/types.ts 에 추가

export interface CoachItem {
  name: string;
  role: string;                 // "감독" | "코치" | "트레이너"
  photoUrl: string | null;
}

export interface TeamSquadPlayer {
  playerSeq: number | null;
  name: string;
  number: number | null;
  position: string | null;
}

export interface TeamDetailResponse {
  url: string;
  teamNum: number;
  name: string;
  gender: "M" | "W";
  logoUrl: string | null;

  intro: string | null;         // 소개 본문 (줄바꿈 유지)
  foundedYear: number | null;   // 본문에서 "2016년 2월에 창단" → 2016
  homeTown: string | null;      // "청주시"
  homeStadium: string | null;
  address: string | null;
  snsUrl: string | null;        // 인스타그램 등

  coaches: CoachItem[];
  squad: TeamSquadPlayer[];

  // /api/ranking 재사용
  rank: number | null;
  points: number | null;
  played: number;
  wins: number;
  draws: number;
  losses: number;
  goalsFor: number;
  goalsAgainst: number;

  // 시즌 경기 결과 (앱이 추이 그래프를 그린다)
  results: ("W" | "D" | "L")[];
}
```

### 파싱 주의

- **`foundedYear`·`homeTown`을 소개 본문에서 정규식으로 뽑는 건 취약합니다.**
  전용 필드가 페이지에 있으면 그걸 쓰고, 없으면 본문에서 추출하되
  실패 시 `null`로 두세요. 앱은 null이면 그 카드를 숨깁니다
- 소개 본문은 `<br>`/`<p>`를 줄바꿈으로 바꿔 **줄바꿈을 살려서** 주세요.
  앱이 `더보기`로 3줄까지만 먼저 보여줍니다
- 연혁(history)은 실측에서 확인하지 못했습니다. 페이지에 있으면
  `history: { year: string; text: string }[]`를 추가하고, 없으면 필드를
  만들지 마세요 (앱은 빈 배열이면 섹션을 숨깁니다)

## 캐시

TTL 24시간. 구단 소개는 거의 바뀌지 않습니다.
단 순위·경기 결과 부분은 `RankingService`/`ScheduleService`의 캐시를 따릅니다.

## 검증

```bash
curl -s 'http://localhost:3000/api/team/132?gender=M&season=2025&type=1' | jq '{
  name, foundedYear, homeTown,
  introLength: (.intro | length),
  coaches: (.coaches | length),
  squad: (.squad | length),
  rank, points, wins, losses,
  results: (.results | length)
}'
```

기대값 (SK호크스):

- `name` `"SK호크스"`
- `foundedYear` `2016`
- `homeTown` `"청주시"` (본문에서 추출 가능하면)
- `introLength` 200자 이상
- `squad`가 비어 있지 않음 — 02번의 선수 데이터와 이름이 일치해야 함
- `rank`, `points`가 `/api/ranking`의 값과 동일

기존 목록 API가 안 깨졌는지도 확인:

```bash
curl -s 'http://localhost:3000/api/team?gender=M' | jq '.teams | length'
```

## 파싱이 깨질 때

- 탭 하나를 못 읽으면 그 부분만 빈 값 (`coaches: []`, `intro: null`)
- 순위 조회가 실패하면 순위 필드는 `null`/`0`, 나머지는 정상 반환
- 전체가 깨져도 500이 아니라 최소한 `name`·`logoUrl`은 목록 API에서 채워 주세요
